# Нохчо Work

PWA: биржа разнорабочих в Чеченской Республике. Заказчики публикуют бытовые и
строительные задачи, исполнители берут их и размещают свои объявления об услугах.
Mobile-first (базовая ширина 390px), только тёмная тема, интерфейс на русском.

**Бэкенда пока нет. Весь проект работает на моках.**

## Стек

React 19 · TypeScript strict · Vite · MobX 6 · React Router 7 · Tailwind v4 · lucide-react

Никаких UI-библиотек (MUI, Ant, shadcn, Radix) — компоненты пишем свои.
Новую зависимость не ставить без моего разрешения.

## Структура

```
src/
  api/         types.ts, client.ts, mock/{delay.ts,fixtures/}
  stores/      session.ts, orders.ts, ads.ts, chat.ts, root.ts, context.tsx
  pages/       по папке на экран, внутри может быть свой components/
  components/  ui/ layout/ order/ ad/ chat/
  lib/         format.ts, geo.ts, hooks/
  styles/      theme.css
```

Три правила вместо архитектурных слоёв:

1. **Страницы только компонуют.** Данные берут из сторов, разметку — из компонентов.
   Ни запросов, ни вычислений, ни бизнес-правил внутри страницы.
2. **Все данные только через `api/client.ts`.** Ни один компонент и ни один стор
   не обращается к фикстурам напрямую и не знает, что за клиентом моки.
3. **Состояние данных только в `stores/`.** `useState` допустим исключительно для
   локального UI: открыт лист, сфокусировано поле, развёрнут блок.

Компонент нужен одной странице — держим в `pages/<Page>/components/`.
Понадобился второй — переносим в `components/<домен>/`. Не раньше.

## Стили

Тема описана в `src/styles/theme.css` через `@theme`. Это единственный источник
цветов, радиусов, шрифтов и отступов.

- Только семантические классы из темы: `bg-surface`, `text-second`, `text-accent`,
  `rounded-card`, `border-line`.
- **Запрещены** произвольные значения в скобках: `bg-[#4CAF50]`, `p-[13px]`, `text-[15px]`.
- **Запрещена** палитра Tailwind по умолчанию: `gray-400`, `green-500`, `zinc-800` и подобные.
- `@apply` не используем. Повторяющийся набор классов — это повод сделать
  компонент в `components/ui`, а не алиас в CSS.
- Порядок классов — по правилам `prettier-plugin-tailwindcss`.
- Минимальная область нажатия 44px: аудитория работает в перчатках на улице.

Точные значения токенов — в `docs/design-tokens.md`.
Эталон вида — прототип в `docs/prototype/index.html`.

## MobX

- Стор — класс с `makeAutoObservable(this)` в конструкторе.
- Мутации только в методах стора. Компонент никогда не пишет в поля стора напрямую.
- Компоненты, читающие стор, оборачиваем в `observer` из `mobx-react-lite`.
- Доступ к сторам — только через `useStores()` из `stores/context.tsx`.
- Асинхронные методы: флаги `isLoading` и `error` в сторе, а не в компоненте.
- Производные значения — через `get`-геттеры, а не пересчётом в рендере.

## Данные

Функции в `api/client.ts` — это контракт, который позже закроет PocketBase.
**Сигнатуры менять нельзя**, меняется только реализация под капотом.

Моки: фикстуры в отдельных файлах, задержка 300–600 мс, флаг имитации ошибки,
переключение реализации через `VITE_API_MODE`.

Фикстуры правдоподобные: Грозный и села Чечни, реальные улицы, чеченские имена,
цены 1 500–15 000 ₽.

## Предметные термины

- Роли: `seeker` — исполнитель, ищет работу; `client` — заказчик, публикует заказы.
- Статусы заказа: `searching` → `assigned` → `in_progress` → `done`, плюс `cancelled`.
- `ServiceAd` — объявление исполнителя о своих услугах, не заказ. Единицы цены:
  `hour` / `day` / `shift` / `negotiable`.
- Вход только через Telegram, номер телефона — резервный способ.
- Оплаты внутри приложения нет: расчёт наличными вне платформы. Не придумывать
  кошельки, эскроу и комиссии, кроме уже нарисованного в макете блока баланса.

## Код

- Именованные экспорты. `default` — только у страниц для роутера.
- Никаких `any` и никаких `as`, кроме `as const`.
- Тексты интерфейса на русском, прямо в компонентах (словарь не заводим — локализации не будет).
- Форматирование цен, расстояний и дат — только через хелперы из `lib/format.ts`.
- Файл больше 150 строк — повод разделить.
- Каждый экран с данными обязан иметь три состояния: загрузка (скелетоны),
  пустой результат, ошибка с кнопкой повтора.

## Как со мной работать

- Перед задачей, затрагивающей больше трёх файлов, сначала покажи план и дождись «да».
- Один экран за один заход. Не собирать несколько страниц подряд.
- Не рефакторить и не переименовывать то, о чём я не просил.
- Не выдумывать экраны, поля и функции, которых нет в макете. Не хватает данных —
  спроси, а не додумывай.
- Не хватает компонента в `components/ui` — сначала скажи мне, потом создавай.
- В конце захода перечисли, что осталось незакрытым.
